# 產品需求文件 (PRD) - 任務管理與追蹤系統

## 1. 專案概述

### 背景與動機
在日常生活與工作中，任務繁雜且容易遺忘。為了提升工作效率，使用者需要一個直觀、易用的系統來建立、分配與追蹤各項任務的進度。

### 目標用戶
- **學生**：追蹤作業、報告與學習計畫。
- **上班族**：管理工作事項、專案時程。
- **團隊管理者**：分配任務給成員並監控整體進度。

### 核心價值主張
提供一站式的任務管理平台，讓使用者能清晰地掌握「誰在什麼時候該做什麼事」，並透過提醒與紀錄功能，確保任務能如期完成。

---

## 2. 功能需求

### 2.1 任務建立
- **使用者故事**：作為一名使用者，我希望能夠建立新任務並設定標題、描述與截止日期，以便紀錄待辦事項。
- **詳細描述**：包含標題、內容描述、優先等級、截止日期。

### 2.2 任務分配
- **使用者故事**：作為一名團隊管理者，我希望將任務分配給特定的成員，以便明確責任歸屬。
- **詳細描述**：可以選擇系統中的使用者進行任務指派。

### 2.3 進度追蹤
- **使用者故事**：作為一名使用者，我希望能夠更新任務狀態（待處理、進行中、已完成），以便隨時掌握進度。
- **詳細描述**：提供狀態變更功能，並在列表頁面顯示當前進度。

### 2.4 提醒通知
- **使用者故事**：作為一名使用者，我希望在任務即將到期時收到提醒，以便避免遺漏重要事項。
- **詳細描述**：系統會標示出即將到期的任務（例如 24 小時內）。

### 2.5 紀錄與查詢
- **使用者故事**：作為一名使用者，我希望能夠查詢過去的任務紀錄，以便進行回顧與統計。
- **詳細描述**：提供關鍵字搜尋與歷史紀錄過濾功能。

---

## 3. 非功能需求

### 技術限制
- **後端**：使用 Flask 框架。
- **前端**：使用 Jinja2 模板引擎進行頁面渲染。
- **資料庫**：使用 SQLite 儲存任務與使用者資料。

### 效能與安全考量
- 頁面載入時間應在 1 秒內。
- 資料庫連線應妥善管理，避免資源洩漏。
- 基礎的資料驗證（如必填欄位檢查）。

---

## 4. MVP 範圍

| 層級 | 功能 |
| :--- | :--- |
| **Must Have** | 任務建立、任務狀態更新（進度追蹤）、任務列表顯示、SQLite 資料儲存 |
| **Should Have** | 任務分配、截止日期設定、基礎搜尋功能 |
| **Nice to Have** | 提醒通知系統、優先等級分類、圖表統計 |
